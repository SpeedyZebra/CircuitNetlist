# Route-Validated Optimization Audit

Milestone 3A added placement scoring and bounded local search, but candidate acceptance was based on pre-routing geometry. That was enough for hard-overlap repair, but not enough for safe soft optimization.

## Initial Scoring Before 3B

`PlacementScorer` scored a layout using:

- Component body overlap and duplicate position hard violations.
- Locked/manual component movement and locked-obstacle hard violations.
- Approximate component clearance.
- Estimated Manhattan net length from pin coordinates.
- Estimated bend count.
- Wrong-facing visual pin directions.
- Functional flow, group compactness, alignment, page area, and aspect ratio.

This score did not run routing. It was a useful prefilter, not proof that the final schematic was better.

## Candidate Generation Before 3B

Candidates were generated by moving topology groups or single components by deterministic grid offsets. Strong topology patterns were considered first, then remaining movable components. Candidate selection chose the lowest placement score that improved hard constraints or, when enabled, soft score.

## Missing Validation Before 3B

3A did not route every candidate. It also did not build a canonical scene for each candidate or run visual DRC before acceptance. That meant a candidate could reduce estimated wire length while causing final routed problems such as:

- `DRC_WIRE_SYMBOL_OVERLAP`
- `DRC_WIRE_WIRE_OVERLAP`
- `DRC_WIRE_TEXT_OVERLAP`
- Component-body collisions after movement
- Router warnings or missing endpoint routes

Known risky examples were:

- `examples/555_timer_50_duty_astable.cnet`
- `test_circuits/good/04_repeated_groups/multi_mosfet_4_channel.cnet`
- `test_circuits/good/04_repeated_groups/multi_decoupling_with_rc_filters.cnet`

## Diagnostic Handling Before 3B

Visual DRC was run in regression and app rendering paths, but not inside optimizer acceptance. Expected electrical diagnostics were handled by regression expected-code comparison, not by placement. Placement does not modify circuit connectivity, so expected ERC findings are preserved by keeping the `Circuit` graph immutable.

## Fallback Before 3B

Fallback existed only as a final placement-score comparison. If the optimized placement score was worse than the initial score, the initial layout was restored. There was no last-known route-validated layout.

## Why Numerical Improvement Could Be Worse

Estimated score sees component centers and pin anchors. The final schematic also depends on:

- Router obstacle choices.
- Power-symbol and net-label stub geometry.
- Scene collision bounds, which include symbol padding.
- Text boxes and pin labels.
- Wire overlap cleanup.

A candidate can improve estimated Manhattan distance while pushing a power stub through a symbol or forcing a routed wire across text. This is why 3B separates pre-routing score from final routed quality.

## Performance Before 3B

Mode behavior before 3B:

- `off`: returned a no-op comparison but still used the optimizer object.
- `score_only`: scored the initial layout only.
- `optimize` with hard-only behavior: could still build move units even when the initial layout had zero hard violations.
- Soft mode: could evaluate many candidates cheaply but without final DRC validation.

3B adds fast paths for `off`, `score_only`, hard-only clean layouts, no movable components, all locked components, route-validation budgets, and wall-clock budget exhaustion.

## Solar Example Finding

The solar example had a pre-existing `DRC_WIRE_SYMBOL_OVERLAP` from a VBAT power-stub attachment near CHG1. The attachment chooser used tighter symbol avoidance than scene DRC. 3B aligns the chooser's physical symbol avoidance padding with scene collision padding, fixing the overlap without suppressing DRC categories globally.
